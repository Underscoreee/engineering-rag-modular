# Task 6.1～6.5 开发路线（建议，尚未启动）

本路线依据 2026-10-18 的[接口审查](query-task6-interface-audit.md)和
[数据流设计](query-task6-dataflow-design.md)。Task 6.0 只改设计文档；每个后续阶段需要维护者
明确启动。Document V2.4 不受本路线的 Query 契约建议影响。

## 0. 前置决策与兼容政策

| 门槛 | 推荐选择 | 依赖与验收 |
| --- | --- | --- |
| C1 两类意图 | 独立 ADR 批准版本化 processing_intent 两类字段，保留旧 QueryIntent 语义 | 6.1 前必须确定；旧 JSON、新 JSON、严格旧读取方和迁移策略全覆盖；不直接替换五类旧枚举 |
| D1 LLM 边界 | 为 Query/未来 Generation 建立共享类型化结构化调用能力；先选服务商/本地模型及数据政策 | 独立授权的契约/适配任务，可作为 6.1 前置子任务；不复用答案生成 Protocol，不要求绑定特定 SDK |
| D2 目录来源 | 首版用人工可信且版本化的元数据快照，通过依赖注入访问 | 快照含标准代码、名称别名、版次/修订、document_id、可用条文和双索引范围；没有可信数据不宣称存在性验证 |
| C2 单路模式 | 首版仅 hybrid，对 keyword/vector 显式 unsupported | 6.4 前确认能力子集；若要求三种模式，则先批准单路可执行计划和依赖设计 |
| C3 澄清/警告 | 首版用类型化异常 + 私有运行记录，上层负责澄清 | 如必须在成功结果内返回状态，需先批准 QueryResult 的版本化扩展；不能用空 evidence 伪装失败 |

本任务没有确定 LLM 服务商、模型、网络端点或密钥，也没有调用任何模型。公共契约变更只能在
单独批准的范围实施，同步消费者、示例和契约测试，不得顺带改检索或 Document 模型。

## 1. Task 6.1：Query Understanding

- 目标：只识别 acquisition/exploratory 两类处理意图与有原文依据的过滤候选，完成验证/消歧。
- 前置：C1 意图契约决议、LLM 类型化能力与测试替身、可信目录数据范围、失败状态政策。
- 输入：QueryRequest、注入模型能力、可信目录快照、内部配置；输出：拟议内部严格 Understanding
  结果和已验证 SearchFilters（含候选来源/未采用原因的私有诊断），不是直接检索结果。
- 允许范围：`modules/query/internal/` 下理解、候选验证、目录适配、配置、错误与测试；
  `modules/query/INTERFACE.md` 和理解阶段文档。共享 contracts/LLM 基础设施只能按前置独立授权修改。
- 禁止：改 Parser/Chunking/Keyword/Vector/Hybrid/Generation；不做 Rewrite、Expansion、HyDE，
  不实现完整 execute，不直连索引。
- 单测：两类意图、非法/缺失/未知字段、纯空白、上下文边界、同名多版、显式标准不存在、
  LLM 编造 ID、已有范围求交/空交集、强条未知、目录不可用、结构化修复预算、超时分类。
- 验收：每个采用条件有可信匹配依据；显式范围不被扩大；模型错误/未匹配与正常空结果分开；
  真实模型 smoke 与注入式测试分列；无独立人工标签时不报告意图准确率。
- 下游：为 6.2 提供确定的阶段输入与不可变保护条件；为 6.3 提供处理意图。

## 2. Task 6.2：Query Rewrite

- 目标：改正口语、错别字、术语表达，保留编号、数值、单位、否定词、公式符号和适用条件。
- 前置：6.1 输出接口和 LLM 依赖可用；先定义保护项提取及校验政策。
- 输入：原问题、受限历史、理解结果；输出：拟议内部主改写结果、保护项校验与回退记录。
- 允许范围：Query 内 rewrite、保护/校验、测试、接口与设计文档；Prompt 仅在此任务授权后编写。
- 禁止：改标准/条文事实或显式过滤；不触碰检索模块，不实现完整 execute，不实现探索增强。
- 单测：标准代码年份、复合条文号、单位转换误改、负号/不等号、否定词、上下限、多条件、
  含糊历史、不合法结构化输出、内容不可信、有限重试、回退后仍保留原始条件。
- 验收：失败时清晰回退原问题；每个保护项都有自动反例；输出有模型/提示/规则版本。
- 下游：为 6.3、6.4 提供唯一主改写，不把多个阶段的文本副本视为不同证据。

## 3. Task 6.3：Query Expansion + HyDE

- 目标：仅在 exploratory 且配置开启时执行有界扩展和假设文档生成，分离两路文本用途。
- 前置：6.1 两类意图可靠表示、6.2 保真主改写、增强输出长度与调用预算。
- 输入：主改写、保护条件、处理意图和开关；输出：拟议内部扩展列表、可空 HyDE、两路文本候选、
  生成来源/采用状态；公共计划只在既有合法字段及已批准意图字段中投射。
- 允许范围：Query 内 expansion/hyde、文本组合/预算、测试和阶段文档。
- 禁止：HyDE 进入 BM25、SearchFilters、evidence 或规范引用；不在此阶段新增多查询融合；
  不改 Vector 的固定 query_instruction，不改 Keyword/Hybrid。
- 单测：acquisition 零增强调用、开关关闭、扩展最多配置数、同义重复、保护条件冲突、
  单阶段失败独立回退、长文本预算、HyDE 不进入关键词、模型臆造编号不得形成过滤或事实。
- 验收：输入固定时组合顺序确定；无 HyDE 仍可用主改写规划；真实模型产物标记假设；
  无标签不得声称召回收益。
- 下游：6.4 将两个最终单字符串放入 Hybrid 子请求；复杂 fan-out 不在首版。

## 4. Task 6.4：Retrieval Planning 与 Hybrid 集成

- 目标：在已批准的契约范围实现 QueryService.plan/execute，复用现有 Hybrid Protocol。
- 前置：6.1～6.3 可独立通过；C2 模式政策、索引/Collection/模型身份、候选上限和结果状态明确。
- 输入：QueryRequest + Query 内部配置 + 注入的 LLM/目录/Hybrid/观测能力。
  输出：RetrievalPlan 与 QueryResult，沿用现有公共结果，除非此前独立批准版本变更。
- 允许范围：Query 的 api、内部 planner/service/config/errors、独立测试、接口文档、
  组合示例和独立集成测试。组合根可用公开 API，Query 内只能用公共 Protocol。
- 禁止：修改 Task 3～5 算法、重算 Embedding/融合、数据库发现标准、实现 Generation 或答案引用生成。
- 单测：plan 不调用检索；execute 内部规划一次并调用一次 Hybrid；输入不被修改；两路文本正确、
  可信 filters 保持一致；候选数/最终 top_k 区别、部署上限、两索引名、合法策略、权重、模式拒绝、
  正常无命中、基础设施异常、QueryResult 实际计划与 evidence 顺序/身份完整性。
- 验收：Protocol 一致、JSON 往返、无跨模块内部导入；真实 Hybrid 集成使用隔离虚构 Chunk，
  不改用户知识库；真实服务缺失应明确 BLOCKED/PARTIAL，不能用替身结果冒充真实集成。
- 下游：6.5 用同一公开入口比较不同增强配置；未来 Orchestrator 独立接入 Generation。

## 5. Task 6.5：人工 Golden Dataset 与端到端评估

- 目标：评价理解、过滤、改写保真和真实检索收益，记录延迟、失败率、用量与可核算成本。
- 前置：6.4 稳定入口、确定的语料/索引快照、授权测试内容、人工复核流程和模型配置。
- 输入：建议评估 Artifact 记录 sample_id、原问题/上下文、两类意图标签、预期过滤范围、
  保护项、相关 chunk_id 与等级、文档/版次/快照、标注者/复核状态与版本。这里只设计数据格式，
  不假称当前仓库已有该数据集；Query 意图标签与检索相关性标签分别验真。
- 输出：按配置对照的 EvaluationReport 或私有详细报告、失败样本、原始运行记录。
- 允许范围：Query 评估数据/测试、独立小型 evaluation 适配、文档和运行入口；若扩公共评估 DTO
  必须单独批准。优先复用现有 EvaluationRequest/Report，不能把描述模型说成已有指标计算器。
- 禁止：修改业务算法来迎合测试标签、拿 Parser/Chunking Golden 当检索金标、用未复核标签算准确率、
  自动重建用户索引或对 LLM 全文输出做不受控记录。
- 单测：两类混淆矩阵、过滤匹配/歧义、保真错误、Recall@K/MRR/nDCG@K 手算例、零命中、重复
  chunk、未复核样本排除、无相关标签、空分母、语料版本冲突、超时/费用未知值。
- 验收：固定模型/提示/索引/数据版本；比较原始问题、Rewrite、Rewrite+Expansion、Rewrite+HyDE、
  可选组合，以及 BM25/Vector/Hybrid 基线。需要独立单路基线时由评估组合入口调用各模块公开 API，
  不让 Query 绕过 Hybrid。只在有人工依据和可比运行条件时报告指标。
- 延迟区分模型阶段、检索、总耗时与冷/热启动；成本仅按实际 token 和记录的价格版本计算，
  价格/用量未知时留空，不造估值。没有真实 Gold 则交付标注队列并报告评估 BLOCKED。
- 后续：评估结论仅提交维护者验收，不自动启动 Generation。

## 6. 每阶段共同门槛

所有任务先检查工作区；公共数据唯一来源为 contracts。阶段独立测试不依赖真实数据库或大型
模型，使用注入替身；另设显式启用的真实模型/Hybrid 测试并分别报告。回归执行该模块、
contracts/architecture、完整 pytest 与 Ruff，检查 diff 未越界，不自动提交。

除独立批准的契约调整外，禁改公共 Schema/Protocol，尤其冻结 Document V2.4。
LLM SDK、模型下载、密钥和网络调用只有在具体实施任务授权且配置可用时才发生。

## 7. Task 6.0 交付与待决策

交付三份设计文档；不修改现有 Query INTERFACE.md，以保留其“只有接口声明”的真实性。
目前待维护者确定的是第 0 节的意图版本方案、LLM 接入/数据政策、可信目录来源、hybrid-only
能力子集以及异常式澄清是否满足首版产品要求。两路不同查询文本和 QueryResult 的 plan/evidence
映射已经可直接复用，不需要新增公共 RetrievalRequest。
